# Search within chat

Herd's Search searches conversation text, titles, and paths already synchronized
to this device, including saved history while offline. All hosts is the default;
Current view limits conversation results to the selected host and workspace.
Existing tab/path matches appear under Agents in this view.

Conversation results are grouped and paginated, with up to three excerpts each.
User and assistant messages rank above conversation metadata, reasoning, plans,
and notices. Tool output and file changes have lower priority, in that order.
Tap an excerpt to open the live or saved conversation at that occurrence, with
tool details and changes expanded. The reader works independently of the
original pane. Back returns to the search and preserves its query and page.

Rust maintains document rows and Unicode trigram candidates in conversations.db;
the complete folded substring is checked before returning a match. One- and
two-character queries search the stored folded rows. Checkpoint updates reconcile
changed documents in the same transaction, and authoritative deletion removes
their index entries. The schema migrates existing checkpoints in place and
backfills one conversation at a time on the database worker. Herd shows progress
while backfill runs. Live native projections supersede saved results and refresh
by revision, independently of checkpoint timing. Queries return only bounded
excerpts and identities to JavaScript. Results are capped at 500 conversations.

Use Find (the magnifying glass) in the bottom rail to search the active view:
chat searches the current conversation, and terminal searches terminal output.
Chat search works across OpenCode, Codex, and Claude Code, including
loaded cached history while offline.

Search is literal and ignores case. It covers user and assistant text, reasoning,
plans, notices, errors, tool names/arguments/output, loaded paths, diagnostics,
and file changes present in the normalized transcript. It does not fetch missing
remote history. Find remains scoped to the current conversation; use Herd for
search across conversations.

The search panel shows four candidate excerpts per page. Tap a candidate to jump
directly to it; page arrows select the first result on the adjacent page.
Previous / Next wraps through individual occurrences in transcript order.
Selecting a result opens its tool details or file changes, highlights the
containing row, and scrolls it below the search bar. Matching visible text is
highlighted inside prompts, Markdown, code, tool output, and diffs. Rendering
adds highlight spans without modifying Markdown, syntax colors, links, or copied
text. Source-only matches (such as Markdown link destinations) still appear in
the candidate excerpts. Revealed rows stay
open when search closes. Opening search pauses automatic following; Latest
resumes it. Leaving the chat closes search and releases the index.

Rust constructs search documents directly from its normalized transcript model
and owns case conversion, bounded excerpts, matching, selection, and reconciliation
as the transcript changes. Live indexes refresh when the native revision changes;
offline indexes restore the saved checkpoint on the conversation database worker.
Document construction and matching run off the UI thread. React Native sends
queries, coalesces refreshes every 150 ms, and controls the list using the row
anchors returned with each result. Transcript content is never sent back through
JavaScript for indexing. Results are limited to the first 500
occurrences; `500+` means the query should be narrowed. No search text or transcript
content is sent to an external service or included in search diagnostics.

Terminal Find uses the same four-candidate panel, with case-sensitive and regular
expression options. Excerpts come from the active terminal buffer. Selecting a
candidate uses terminal cell coordinates, including wide characters and wrapped
lines. Output refreshes results without moving the viewport; explicit selection
or Previous / Next reveals the selected occurrence. Terminal results are also
capped at 500.

The native API changed, so a native app rebuild is required; Metro reload alone
cannot add native transcript search, direct result selection, or native Markdown
highlight props. The
`react-native-enriched-markdown` patch includes both shipped TypeScript specs and
Android/iOS generated props because the dependency ships generated native code.
The `react-native-code-highlighter` patch exposes rendered token ranges so search
can highlight across syntax tokens. Android native bindings are generated by
`nix develop -c bash scripts/build-android-rust.sh` for arm64 only. iOS builds use
the existing device build workflow.

Tests cover literal matching, Unicode excerpts, result bounds, live snapshot
replacement, selection retention, query scheduling, cached chats, tool/diff
expansion, result navigation, and avoiding repeated jumps while streaming.
Native device validation should additionally check keyboard resizing, very long
tool output, and switching between conversations while search is open.
