# HyperFrames production brief

- Product: Whip, a native Android and iOS client for Herdr.
- Audience: developers already using coding agents on remote machines.
- Promise: supervise and interact with a whole Herdr workflow from a phone over
  the user's own SSH connection.
- Runtime: 43.2 seconds.
- Master: 1920×1080, 30 fps, H.264/AAC.
- Music: **Techno Fights** by Alejandro Magaña (A. M.), Mixkit Stock Music
  Free License; conformed from 140 BPM to the 128 BPM motion grid.
- Autoplay-safe: every claim is understandable without sound.
- Evidence: current Whip screen recordings and official Herdr desktop assets occupy
  most of the runtime.

## Story beats

1. Land an oversized Whip icon, then join it to the Herdr icon to establish Whip as Herdr's mobile client.
2. Show the full phone, zoom onto Oracle and thinker, pull out before tapping Add Host, then zoom onto the QR and manual options. Oracle uses the saved DNS name oracle.
3. Establish the full phone on All hosts, then zoom into the upper half for thinker → All spaces → Whip → Run. Cut the idle hold between space selection and Run; show “Live everywhere” once.
4. “Stay connected, whip anywhere anytime.” Start in Settings, show the native Agent finished banner, then tap it to open Whip on the matching completed host-list conversation. Delete the idle 00:14–00:15 interval and preserve the tap-through.
5. Zoom onto the terminal’s bottom half, visibly scroll terminal output, and swipe both the control buttons and tab rail.
6. Name the feature “Native Chat View.” Zoom directly onto the native Chat diff while expanding, collapsing, and copying it; then show the composer.
7. “Let a remote agent use your phone as a tool.” Ask What hosts do I have in Whip? through Reverse Control and show the real host list, then browse the README.
8. Swipe up through remote files, open the actual project README preview, and inspect a Git diff.
9. Return to Herd beside the laptop and land the store links and install QR.

## Capture and motion constraints

- Record the original configured iPhone 17 Pro simulator, with
  the configured background image and Rancher glass appearance intact.
- Map unframed recordings onto the real iPhone model; never nest the README's
  framed mockups inside its screen.
- Show real UI interactions in each feature shot. The host-list question is submitted to the dedicated demo agent and answered using Whip’s actual hosts.list tool.
- Let the camera establish the whole app before approaching a feature. Keep
  host cards, add-host choices, host/space rails, terminal controls, and the diff large enough to read.
- Retain the existing desktop capture, device models, opening sound effects,
  native notification styling, and licensed soundtrack. No narration is added.

## Reference-derived direction

- Reveal the product in the opening second instead of leading with a title card.
- Alternate full-device shots with close UI crops to create camera rhythm.
- Keep each scene to one short claim and place copy opposite the product.
- Land scene changes on the soundtrack beat and animate the product continuously.
- Reserve a distinct, minimal closing shot for the brand and release message.
- Use device rotation, masked color fields, match cuts, and oversized crops—not
  simple slide transitions.
- Reuse shapes across cuts: the whip loop becomes an orbit, the orbit becomes a
  sync path, and the sync path carries focus from desktop to mobile.
- Treat the phone as a dual-sided 3D object, not a skewed screenshot: begin on
  an oversized back plate, pass through the thin hardware edge near 90°, reveal
  the live screen, then scale and settle into the interface composition.
